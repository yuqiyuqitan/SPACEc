# Changelog

## Version 2.0.0 (2026-11-25)

- FIX: `save_mask_as_png=True` now actually writes a PNG overlay instead of a misnamed `.npy` file
- FIX: `read_segdf` now adds a `unique_cell_id` column (and, for the Cellpose path, a `label` column) so cells stay uniquely identifiable and traceable to their mask label across concatenated regions; `make_anndata` picks this up automatically to set `adata.obs_names`
- Add `cell_segmentation(save_mask=True)` to persist raw segmentation masks, and `hf.hf_attach_masks`/`hf.hf_load_masks` to attach them to an AnnData object (`adata.uns["masks"]`) for per-cell pixel lookup, including cells removed by `size_cutoff`
- FIX: `compensate_cell_matrix` joined compensated intensities back onto `df` by row *position*, not by mask label -- any row reordering, region mismatch, or `size_cutoff`-filtered mask silently produced wrong per-cell values (or crashed, on non-consecutive mask labels). It now joins on `df`'s `label` column (added by `read_segdf`), validates that the mask and `df` correspond to the same region, and requires `region=...` on multi-region input instead of silently mixing regions. **Any previously-produced compensated values should be treated as unverified and regenerated.**
- Add `hf.hf_load_image_dict` (complementing `hf.hf_load_masks`) to load a region's channel images by path, so spillover compensation no longer requires unpickling a saved `cell_segmentation` output dict
- **BREAKING:** `compensate_cell_matrix` no longer takes a `device` argument. Compensation now runs on the CPU; remove `device=...` from existing calls
- `compensate_cell_matrix` is dramatically faster and no longer memory-bound. The cell adjacency matrix (only ~7 non-zeros per row) was being materialized dense and solved with a dense least-squares routine: 1.6 GB and 72 s at 20,000 cells, and simply unallocatable at 57 GB for 120,000. It is now stored sparsely and solved directly, taking ~3.5 s and ~10 MB at 120,000 cells, so large regions no longer need to be tiled. The compensation model is unchanged from CellSeg; solving in float64 rather than float32 also cuts the solve residual from ~1e-3 to ~1e-13, so compensated values shift by ~1e-5 relative
- FIX: `compensate_cell_matrix` used `torch.linalg.lstsq`, whose only CUDA driver (`gels`) assumes a full-rank matrix and returns unusable values otherwise. A singular adjacency matrix now warns and falls back to the dense least-squares solver CellSeg used, which returns the minimum-norm solution
- Add `pl.expression_on_masks` to paint continuous marker (or numeric `obs`) values onto attached segmentation masks -- the continuous counterpart to `pl.plot_masks`, replacing the manual label-lookup snippet at the end of tutorial 03.1
- GPU clustering (`sp.tl.clustering(..., clustering="leiden_gpu")`) works again with current rapids-singlecell. The optional `rapids` extra is replaced by `rapids12` and `rapids13`, matching rapids-singlecell's per-CUDA distributions: `pip install 'spacec[rapids13]' --extra-index-url=https://pypi.nvidia.com` (or `rapids12`). RAPIDS stays optional -- it is only needed for `leiden_gpu`
- **BREAKING:** `install_gpu_leiden` is removed. It pinned rapids-singlecell 0.9.5 and RAPIDS 24.02 wheels, and was never exported on `sp.tl`. When rapids-singlecell is missing, `clustering(clustering="leiden_gpu")` now prints the correct `pip install` command for the CUDA version torch was built against before falling back to CPU `leiden`
- Add `sp.tl.subclustering` and `sp.tl.annotate_clusters`, replacing the hand-written chain of `sc.tl.leiden(restrict_to=...)` calls and the fragile `.map()` + identity-dict pattern used to split and annotate clusters in the tutorials. `subclustering` splits one or more clusters *sequentially* (one `restrict_to` call per cluster, chaining onto the accumulating `key_added` column), not as one pooled split. `annotate_clusters` defaults to `missing="keep"`: cluster labels absent from the mapping keep their original label instead of becoming `NaN`, so callers no longer need to re-list every already-annotated label
- Add `sp.tl.clustering_tree` and `sp.tl.clustering_report`, which reconstruct and render the lineage recorded by `clustering`/`subclustering`/`annotate_clusters` (`adata.uns["clustering_tree"]` / `adata.uns["clustering_report"]`) as an ASCII family tree or a narrative report -- survives `.h5ad` save/reload
- `subclustering` standardises on `random_state=seed` (matching `clustering`), whereas the old notebook pattern passed `seed=` directly to `sc.tl.leiden`, which leidenalg consumes instead -- subcluster label *assignment* may therefore differ slightly from previously committed notebook output even though the method and resolution are unchanged
- The interactive clustering GUI's subclustering tab now splits its comma-separated cluster list sequentially via `subclustering()` instead of pooling them into a single `restrict_to` call -- a behavior change and a fix, matching the new notebook wrapper. The annotation tab now also renders the clustering lineage tree after "Apply annotations"
- Add `sp.pl.cluster_qc`, which plots the per-cell properties recorded during segmentation (cell area, nuclear-stain intensity, and any other numeric `adata.obs` column) as one box per cluster, with a reference line at the dataset-wide median -- so a cluster made of segmentation fragments or edge-truncated cells can be spotted before it is written off as noise. Coordinates and identifier columns are excluded automatically; `return_data=True` also returns the per-cluster median table. Reports measurements only: no thresholds, flags or automatic verdicts
- Add `compensate_cell_matrix(..., exclude_channels=...)` to leave named channels uncompensated. Every `image_dict` channel except the synthetic `segmentation_channel` was compensated, including the nuclei stain -- which is not a panel marker, and whose raw column was overwritten under `overwrite=True`. Excluded channels are not solved for, keep their raw values, produce no `_compensated` column, and need not be present in `df`
- FIX: pin `pandas<3`. pandas 3.0 makes `str` (`pd.arrays.StringArray`) the default string dtype, which anndata refuses to write, so `adata.write_h5ad(...)` failed with `RuntimeError: anndata.settings.allow_write_nullable_strings is False` while writing `obs`'s `_index`
- Add `sp.tl.suggest_annotation`, which proposes a cluster -> cell type mapping from a marker panel (`{cell_type: [markers]}`): each marker is z-scored across clusters, each cell type scored as the mean z of its markers, and the winner taken unless it is too weak (`min_score`, -> `"Unknown"`) or too close to the runner-up (`min_margin`, -> `"Mixed"`). It writes nothing to `adata` -- the mapping is returned so it can be edited and then applied with `annotate_clusters`, which records it in `adata.uns["clustering_report"]`/`["clustering_tree"]` like any other annotation step. `mode="manual"` walks through the clusters one at a time in a notebook, showing a per-marker z-score barplot and prompting to accept or override each proposal; `return_scores=True` also returns the clusters x cell types score table
- `sp.tl.adata_stellar` now uses the installed `stellar-gnn` package (`TKempchen/stellar-py3.12`) instead of a `sys.path` hack onto a manually cloned `snap-stanford/stellar` checkout (Python 3.8/torch 1.9, incompatible with SPACEc's supported Python/torch versions). New `device`, `louvain_flavor`, and `num_parts` params are passed through to STELLAR; `sample_rate` and `seed` now actually take effect (subsampling was previously commented out and no seed was ever set). `install_stellar()` is rewritten to install `torch-geometric`/`torch-scatter`/`torch-sparse` for the installed torch build plus the fork, and is now exported as `sp.tl.install_stellar`. `GitPython` is dropped from `install_requires` since nothing else in the repo needs it
- Add `sp.pl.swarm_box_plot` (legacy name `pl_swarm_box_ad`), the replicate-aware companion of `sp.pl.stacked_bar_plot`: one box-plus-swarm panel per category in `cell_list` (cell type, neighborhood, community), x-axis = `grouping`, one dot per `replicate` (e.g. patient/region). Same arguments as `stacked_bar_plot` (`adata`, `color`, `grouping`, `cell_list`, `norm`, `sub_col`, `col_order`, `plot_order`, `palette`, `savefig`/`output_fname`/`output_dir`, `fig_sizing`, `style`) plus `replicate`. Returns `(df, plot_order)`, where `df` is a long table (`grouping`, `replicate`, `color`, `percent`) ready for statistics; a replicate lacking a category gets an explicit `0`. Misuse (unknown column, `cell_list` not a list, no matching values, `replicate == grouping`, ...) raises a `ValueError` that shows a working example call. The previous unexported `pl_swarm_box_ad(per_cat, sub_list, color_dic, save_name, flip, ...)` drew all categories into one box per group and is replaced -- `pl_swarm_box_ad` now points to `swarm_box_plot` with the new signature (`flip` is dropped)
- `sp.pl.create_pie_charts` is reworked for publication-ready output: every wedge is labelled in a column beside the pie (`name (12.3%)` with `show_percentages=True`, otherwise just `name`), joined to its wedge by a thin elbow leader line that leaves the rim radially; labels keep wedge order on each side, so lines stay clear of the pie and of each other. Small wedges overlapped at the rim before, and so did percentages printed inside wedges; label spacing now follows the font size and axes size, and the pie is rotated so the run of small wedges (<10%) sits at 9 o'clock, beside its labels. Wedges are separated by thin white edges instead of black outlines. No signature change. The figure is now 7 in wide per pie (previously a fixed 15 in, at most 3 pies per row) and the pie itself is smaller, to make room for the labels
- Add `cn_exp_heatmap(..., grouping=...)`: an `adata.obs` column assigning each `cluster_col` value (e.g. cell type) to a major group (Immune, Stroma, ...). Columns are arranged as one contiguous block per group (clustered within the block when `col_clus`, sorted otherwise), with a labeled group color strip on top and white separators between blocks; the column dendrogram is dropped. A cell type assigned to several groups, or to none, raises a `ValueError`. Neighborhood ids are now written inside their row color boxes (the color strip widens to fit long neighborhood names) instead of as tick labels on the far right, and the colorbar label is anchored to the colorbar so it no longer drifts away at other figure sizes. A slim "n cells" bar chart right of the heatmap shows each neighborhood's size, aligned with its row (`show_cn_size=True` by default)
- Add `neighborhood_analysis(..., kmeans_kwargs=...)`: extra keyword arguments forwarded to `MiniBatchKMeans` (and to the elbow scan), e.g. `{"batch_size": 100, "n_init": 3}` to restore scikit-learn's pre-1.0 defaults used by nolanlab/NeighborhoodCoordination. `random_state` still defaults to 0, so results without `kmeans_kwargs` are unchanged
- Add `sp.pl.cn_upset`, an UpSet-style alternative to `sp.pl.cn_map` with the same arguments (`figsize` defaults to the style's double-column size): the neighborhood combinations from `build_cn_map` as columns ranked by frequency, with bars for the fraction of windows, the member CNs drawn as `cn_map`'s colored squares, CN names inside their color boxes as in `cn_exp_heatmap`, and per-CN bars for the fraction of windows containing each CN. `min_freq` defaults to 0.001, the cutoff `build_cn_map` uses for the graph, so both plots show the same combinations -- plus any combination with no parent or child, which `cn_map` cannot draw. The CN label strip, CN rows and left column are sized to their text at the style's font sizes (the figure grows if `figsize` is too small for them), and percentage labels turn vertical, or are left out, when the columns get too narrow for them; `show_values=True` always prints them (shrinking the font if needed), `show_values=False` never does, and `value_decimals` sets their precision. Percentage labels sit a small gap above their bar instead of touching it, and the bar panel leaves room for the tallest one. The bar y axis sits on the right so the CN label boxes sit right next to the matrix
- `tl_calculate_neigh_combs` (run by `build_cn_map`) draws one labeled diagnostic plot instead of two bare line plots and an unlabeled print: ranked combination frequencies, their cumulative sum, the `per_keep_thres` line, and which combinations fall below the 0.001 cutoff for the CN map (new `thresh_freq` argument, used for that shading only). FIX: a `per_keep_thres` below the top combination's share no longer reports a negative frequency
- `sp.pl.cn_map` marks the top combinations with a small black asterisk marker right of each circle, at its height, so it never covers the circle or the squares (the old white text `*` sat above the circle center and was lost on small nodes). The "Total frequency" legend now explains the asterisk ("Top 20 by frequency")
- `sp.pl.plot_top_n_distances` is reworked. The ranking was always `|Δ log2(observed/expected)|` between the two conditions, not a raw distance difference as the docstring claimed; the docstring, title and legend now say so. Each pair's expected (permutation) mean is drawn as a dashed line in its colour (`show_expected=True`), so the gap that drives the ranking is visible next to the observed distances. The legend lists the pairs in rank order with their signed Δlog2FC, the x-axis follows the column order of `dist_table_filt` and is labelled with `condition_col` (it said "Condition" before), and pairs are dodged by default (`dodge=0.3`; was `False`, which stacked points on top of each other). Colours now come from the SPACEc style palette. The function returns the ranked top-n table (with `interaction` and `delta_log2fc` columns) instead of printing it, and raises a clear `ValueError` on an empty `dist_table_filt`. FIX: `errorbars=False` no longer passes seaborn's deprecated `ci=None`. Error bars are still the SE over per-cell means pooled across regions, which understates between-replicate variability; the docstring now says so
- **BREAKING (install):** `louvain` is no longer installed by default; it moved to a new `legacy` extra (`pip install "spacec[legacy]"`). The package is deprecated (0.8.2 is its last release) and needs `igraph<0.12`, while `leidenalg` 0.12 needs `igraph>=1.0`. pip therefore backtracked to the sdist-only `louvain` 0.7.1 and tried to compile igraph's C core, so `pip install` failed on Windows (and on any machine without CMake and a C++ compiler) with `Failed building wheel for louvain`. The extra pins a working set: `louvain==0.8.2`, `igraph<0.12`, `leidenalg<0.12` and `setuptools<81` (`louvain` imports `pkg_resources`, which setuptools 81 removed). Prebuilt wheels exist up to Python 3.11; on 3.12 the extra builds `louvain` from source. Default results are unchanged: `clustering`/`subclustering` with the default `flavor="igraph"`, and all leiden clustering, never used this package. What changes: `flavor="legacy"` with louvain now raises an `ImportError` naming the extra when `louvain` is missing; `adata_stellar(louvain_flavor="auto")` falls back to the `igraph` backend (with STELLAR's warning) instead of `vtraag` on installs without the extra, which gives different partitions when `num_seed_class > 0`; and installing the extra moves both leiden backends to the older igraph/leidenalg releases, so leiden labels can differ slightly between environments with and without it
- FIX: installing from a source tree without usable git metadata (a GitHub ZIP, a copy without `.git`, or a WSL checkout on `/mnt/<drive>` where git refuses the repository for "dubious ownership") no longer fails with `setuptools-scm was unable to detect version`; the version falls back to `0.0.0`
- Add flagging QC to `sp.pp.filter_data` and `sp.pp.remove_noise`: looser `*_flag_*` thresholds write non-destructive `qc_flag_*` columns next to the existing hard-drop filters, so borderline cells can be inspected instead of silently dropped. New QC dashboard (`sp.pp.plot_filter_dashboard`) and summary table
- Add `sp.pp.marker_score_thres`, replacing `zcount_thres` (moved from `sp.pl` to `sp.pp`; `sp.pl.zcount_thres` and `sp.pp.zcount_thres` still work with a `DeprecationWarning`). It returns its thresholds (plus the figure with `qc_dashboard=True`) and no longer calls `plt.show()`
- Noise removal works on all four `sp.pp.format` methods (`zscore`, `double_zscore`, `MinMax`, `ArcSin`), not just z-scores; `positive_thres` sets what counts as positive. `remove_noise` parameters renamed to match (`z_sum_thres` -> `score_sum_thres`, `z_count_thres` -> `count_thres`, and the `*_flag_thres` equivalents); old names still work with a `DeprecationWarning`
- `marker_score_thres`, `remove_noise` and `sp.hf.make_anndata` select markers by name (`marker_list`) instead of by column position (`col_num`/`col_sum`, deprecated), which picked the wrong columns whenever column order changed
- `sp.pp.format` gains `markers=` (the columns to normalize), as an alternative to the `list_out`/`list_keep` pair
- `sp.pp.read_segdf(meta_list=...)` accepts a dict to add several metadata columns at once
- Harmonized parameter names; old names still work with a `DeprecationWarning`: `extra_seg_ch_list`/`additional_channels` -> `membrane_channel_list`, `DNAslice` -> `nuclei_channel` (+ `channel_file`), `color_by` -> `region_column` (`filter_data`), `colors` -> `palette` (`plot_top_n_distances`)
- FIX: tissue extraction functions now support all three `input_format`s (`Multichannel`, `Channels`, `CODEX`), not just `Multichannel`
- FIX: `sp.hf.downscale_tissue` ignored the active plotting style; the `tissue` style now uses readable white text
- `sp.pl.expression_on_masks` accepts a DataFrame plus `masks=`, not only an AnnData
- Add `sp.pl.extended_dotplot`: marker dotplot with optional dendrogram, per-cluster QC blocks and spatial highlight panel, colored by per-cluster z-score by default. `transpose=True` orients it vertically. Replaces `marker_dotplot` for most uses
- Add `sp.pl.patch_QC` / `sp.pl.run_patch_QC` (image patches of a cluster's cells with mask outlines, to check cluster identity on the image), and `sp.tl.add_morphology_features` / `sp.pl.feature_outlier_grid` (per-cell shape and contact features from masks)

- Clustering GUI: the Dotplot tab uses `extended_dotplot`; a GUI-wide cluster/region picker highlights the selection in the UMAP and "Cluster counts" (renamed from "Histogram") and subsets both by region

- `sp.tl.suggest_annotation(mode="manual")`: progress indicator, stop with `q` and continue later via `resume_dict=`, optional `p` to view `patch_QC` for the cluster's top `n_patch_markers` (default 4) markers when `masks`/`images` are passed, and a `style` parameter. The cell-type legend sits below the plot and no longer overlaps the marker labels
